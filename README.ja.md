# DSH Mobile — DeepSeek Harness のホストプラグイン

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語

`@kinocode/dsh-mobile` は、Android アプリ DSH Mobile のための DeepSeek Harness（DSH）プラグインです。次のことができます。

- DSH のサイドバーに出る QR を読み取って、スマホとペアリングする。
- PC で動く HTTPS の接続口を通して、スマホで通常の DSH 画面を使う。
- 承認待ちやエージェントからの質問に、通知から答える。回答はデスクトップと同じ実行中のセッションに届き、どの端末からでも最初の回答が採用される。
- 監視中のセッションのターンが終わったら通知を受け取る。

Android アプリは別に配布していて、このリポジトリには含まれません。非公式のプロジェクトで、DeepSeek 社とは関係ありません。

## 必要なもの

- DeepSeek Harness `>=0.2.1-rc.2 <0.3.0`。まだ安定していない DSH Gateway の内部 API を使うため、対応範囲を固定しています。
- DSH の Web サーバー（`webserver` サービス。DSH デスクトップ版に含まれます）。
- Node.js 22.4 以上（DSH デスクトップ版に同梱の実行環境で足ります）。
- スマホと PC が同じネットワークにいるか、両方が [Tailscale](https://tailscale.com/) につながっていること。
- 通知を使う場合は中継サーバー（[通知と中継サーバー](#通知と中継サーバー)を参照）。

## 導入

DSH の「プラグイン」画面で `@kinocode/dsh-mobile` を追加するか、次を実行します。

```bash
dsh plugin --profile desktop add @kinocode/dsh-mobile
```

そのあと DSH を再起動します。ログに `[mobile-bridge] gateway listening {"origins":[...]}` と出れば動いています。

## スマホとペアリングする

1. DSH のサイドバー下部にある **スマホを接続** を押します。
2. アプリで **QR を読み取る** を押して QR を読み取ります。カメラが使えないときは、**リンクをコピー** で取ったリンクをアプリに貼り付けます。
3. QR は 1 回だけ使え、5 分で期限が切れます。**新しい QR** で作り直せます。

同じパネルに接続中の端末が並び、ここから削除できます。削除した端末はすぐに使えなくなります。

スマホでは、会話を画面いっぱいに使えるよう DSH のサイドバーを隠します。左上の丸いボタンで会話の上に開き、セッションを選ぶか外側をタップすると閉じます。デスクトップ用のボタンも隠します。

スマホでワークスペースを追加するときは、PC のフォルダ選択のウィンドウではなく、スマホに PC のフォルダ一覧が出ます。フォルダをたどるか、パスを入れて **このフォルダを使う** を押します。

## 設定

どの項目も省略できます。プロファイルの `cordis.patch.yml` に書きます。プロファイルの差分はプラグインの設定全体を置き換えるので、残したい項目はすべて書いてください。

```yaml
- id: mobile-bridge
  config:
    relayUrl: https://relay.example.com
    relayEnrollToken: '...'
```

| 項目 | 既定値 | 意味 |
|---|---|---|
| `relayUrl` | `''`（なし） | 通知と、通知からの回答に使う中継サーバー。 |
| `relayEnrollToken` | `''` | 登録済みの PC だけを受け付ける中継サーバー用のトークン。 |
| `gatewayEnabled` | `true` | スマホ用の HTTPS 接続口を開く。 |
| `gatewayPort` | `3543` | 接続口のポート（1024〜65535）。 |
| `gatewayHosts` | 自動検出 | 待ち受ける IPv4 アドレス。プライベートなアドレスだけ指定できます（後述）。 |
| `hostLabel` | PC 名 | スマホに表示する名前。 |
| `previewMaxChars` | `400` | アプリに表示するコマンドのプレビューの最大文字数（50〜4000）。 |
| `stateDir` | `$DSH_HOME/mobile-bridge` | PC の識別情報、接続中の端末、証明書の保存場所（絶対パス）。`$DSH_HOME` の既定値は `~/.dsh`。 |

以前の版との互換性のため、設定の ID は `mobile-bridge`、ログの表示名は `dsh-mobile-bridge` のままです。

## しくみ

- **接続口:** HTTPS はプライベートな IPv4 アドレス（`10/8`、`172.16/12`、`192.168/16` と Tailscale の `100.64/10`）だけで待ち受けます。証明書はプラグインが作る認証局（CA）で発行します。QR に CA の指紋が入っていて、アプリはこの PC についてはその CA だけを信頼します。
- **ペアリング:** アプリが Android Keystore に ECDSA P-256 の鍵を作り、一回限りのコードで公開鍵を登録します。
- **制御の要求:** 承認待ちの一覧の取得、回答、設定の変更は、端末の鍵で署名します。プラグインは署名、時刻（±5 分）、ナンスを確かめ、同じ要求の使い回しを防ぎます。
- **DSH 画面:** ペアリング後、アプリは接続口用のセッションを受け取ります。12 時間有効で、PC の外に出ない秘密情報で署名しています。端末を削除するとすぐ無効になります。接続口が自分でローカルの DSH Web サーバーにログインするので、DSH 自体のログイン情報がスマホに渡ることはありません。
- **実行中のセッション:** プラグインは DSH Gateway のイベントの流れに、プロセス内の所有者クライアントとして参加します。GUI のウィンドウが一つ増えたのと同じ扱いです。承認のリスナーは登録しないので、デスクトップから承認を横取りしたり、デスクトップを飛ばしたりはしません。Gateway は最初の回答を採用し、ほかの場所の表示を閉じます。
- **デスクトップのパネル:** サイドバーのパネルは、所有者だけが使える DSH の API（`/api/dsh-mobile-bridge/*`）を使います。

## 通知と中継サーバー

モバイル回線のスマホからは接続口に届かないので、通知は中継サーバーを通します。プラグインは中継サーバーへの外向きの WebSocket をつなぎっぱなしにします。中継サーバーは Firebase Cloud Messaging でプッシュ通知を送り、スマホからの署名付きの要求を PC に届けます。署名を作ることはできず、DSH 画面や DSH のログイン情報には触れません。

公開の中継サーバーは今のところ用意していません。中継サーバーがなくても、スマホから PC に直接届く間は、通知以外はすべて使えます。

中継サーバーが読める内容は次のとおりです。

- **プッシュ通知:** 既定では、セッション名、ツール名または質問の見出し、最大 3 つの選択肢、状態、内部の ID です。アプリで **ロック画面にコマンド全文を表示** をオンにすると、コマンドのプレビューまたは質問の全文（最大 400 文字）と、ターン終了時のエージェントの最後の返答の先頭 200 文字も加わります。
- **中継サーバーを通る要求:** 暗号化されるのは各端と中継サーバーの間だけで、端から端までではありません。スマホが中継サーバー経由で要求を送ると、承認待ちの一覧（コマンドのプレビュー全体、理由、質問）、セッションの一覧（名前と作業フォルダ）、回答（自由記述を含む）を中継サーバーが読めます。

中継サーバーは、自分で運用しているものか、信頼できるものだけを使ってください。

ロック画面では、スマホが機密情報を表示する設定でない限り、Android は公開用の短い表示だけを出します。DSH を普通に終了したときは、プラグインが未回答の通知の取り消しを試みます（最大 3 秒）。DSH が落ちた場合は、次にアプリが承認待ちの一覧を読み込んだときに古い通知を消します。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| スマホがつながらない | 同じネットワークにいるか、両方で Tailscale を使っているか。ファイアウォールがポート 3543 を止めていないか。PC の IP アドレスが変わったら QR を出し直す。 |
| 「証明書が QR の内容と一致しません」 | 別の PC の QR か、接続口の CA が作り直された。新しい QR を出して読み直す。 |
| 通知が来ない | スマホで通知を許可したか。`relayUrl` を設定し、DSH のログに `relay connected` が出ているか。セッションの権限が承認ありの設定か（「Full access」では承認は発生しない）。 |
| DSH を再起動したらスマホの DSH 画面が白紙になった | DSH の起動が終わってから、アプリを閉じて開き直す。 |
